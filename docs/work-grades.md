# 작업 등급표 (A/B/C) — 1~2주차 범위

> 작성일: 2026년 8월 7일
> 적용 범위: 프로젝트 1~2주차 (환경 구축 · 데이터 · YOLO 1차 학습)
> 3주차 이후(C#/WPF/DB/Excel) 항목은 2주차 종료 시점에 추가한다.

---

## 1. 이 문서의 목적

6주 안에 YOLO, FastAPI, C#, WPF, MSSQL을 전부 직접 구현하는 것은 불가능하다.
반대로 전부 AI에게 맡기면 프로젝트는 완성되지만 면접에서 설명할 것이 남지 않는다.

따라서 **"직접 할 것"에 쓸 시간 예산을 어디에 몰아줄지**를 미리 정한다.
이 문서가 그 기준이며, Claude / Claude Code와 협업할 때의 규칙이 된다.

## 2. 등급 정의

| 등급 | 원칙 | 작업 방식 | 문서화 |
|---|---|---|---|
| **A** | 무조건 직접 한다 | 내가 먼저 작성 → Claude는 리뷰와 힌트만 | `experiment-log.md`, `decisions.md` 등을 **내가 작성**, Claude는 첨삭만 |
| **B** | 같이 한다 | Claude가 뼈대 → 내가 채우고 이해 | 코드 주석 + 파일 상단 설명 (Claude 작성) |
| **C** | 전부 맡긴다 | Claude Code가 처리, 나는 결과만 확인 | `setup-log.md`에 항목당 5줄 (Claude 작성) |

### A등급 작업 절차

```
Claude가 이번 단계의 "명세 + 최소 개념 + 힌트"만 제공
→ 내가 먼저 작성한다 (막히면 힌트를 단계적으로 요청)
→ 동작하든 안 하든 Claude에게 리뷰 요청
→ Claude 버전과 비교하고 차이의 이유를 듣는다
→ 커밋
```

**핵심 원칙: 정답을 먼저 보지 않는다.**
헤매는 20분이 학습의 대부분이고, 그 다음에 보는 정답이 깊게 남는다.

### 막혔을 때 규칙

```
30분 혼자 시도
→ 힌트 요청 (정답 아님)
→ 그래도 안 되면 정답 확인 + 왜 그렇게 되는지 설명 요청
```

### C등급도 기록은 남긴다

이해는 하지 않아도 되지만 기록은 남긴다. 이유는 두 가지다.

- **재현성** — 노트북을 새로 세팅하거나 교육장 PC에서 다시 구축할 때 이 로그가 전부다.
- **면접 재료** — "환경 구축에서 뭐가 어려웠나요"는 실제로 나오는 질문이다.

단, **개념 해설은 넣지 않는다.** C등급을 설명하기 시작하면 A등급으로 승격되고 시간 예산이 무너진다.

## 3. 이해 게이트 (커밋 조건)

각 단계 끝에서 아래를 통과해야 커밋한다. 못 하면 다음으로 넘어가지 않는다.

> 코드를 **보지 않고** 다음을 말할 수 있는가?
>
> 1. 이 파일은 왜 존재하는가?
> 2. 이 함수의 입력과 출력은 무엇인가?
> 3. 실행 흐름에서 언제 호출되는가?
> 4. 실패하면 어떤 오류가 발생하는가?
> 5. 이 코드는 프로젝트의 어느 기능을 담당하는가?

B·C등급은 1번과 5번만 답할 수 있으면 통과.
A등급은 5개 전부 답할 수 있어야 통과.

## 7. 눈에 띄는 패턴

A등급 12개 중 **코딩인 것은 4개뿐**(14, 17, 19 일부, 20)이다.
나머지는 촬영 설계, 규칙 정의, 라벨링, 판단, 기록이다.

이것이 AI 비전 검사 직무의 실제 모습이고, 동시에 좋은 소식이다.

> **"직접 하고 싶다"는 요구와 "6주 안에 끝내야 한다"는 제약이 충돌하지 않는다.**
> 직접 해야 할 것의 대부분이 코드가 아니기 때문이다.
> Claude가 코드를 많이 써도 프로젝트의 핵심은 여전히 내 것으로 남는다.

| 문서 | 작성 주체 | 내용 |
|---|---|---|
| `docs/setup-log.md` | Claude | C등급 작업의 명령어, 목적 한 줄, 막힌 것, 해결 방법 |
| `docs/work-grades.md` | 나 (본 문서) | 등급 기준 |
| `docs/decisions.md` | **나** | 왜 이렇게 결정했는가 |
| `docs/labeling-guide.md` | **나** | 라벨링 규칙 |
| `docs/experiment-log.md` | **나** | 학습 실험 기록, 실패 사례 분석 |
| `docs/daily-log.md` | **나** | 작업 일지 |
| 코드 주석 | **Claude (A·B·C 전부)** | 2026-09-02 변경. 원래 A등급은 내가 썼다 (아래) |

**A등급 문서를 Claude가 대신 쓰면 안 되는 이유:**
"왜 Recall을 우선했는가", "이 실패의 원인은 무엇이라 추정하는가" 같은 것은 **글로 쓰는 과정 자체가 사고**다.
Claude가 써주면 읽을 때는 다 아는 것 같지만, 면접에서 같은 질문을 받으면 그 문장이 나오지 않는다.

내가 먼저 쓰고 → Claude가 "이 부분은 근거가 약하다", "이건 이렇게 반박당할 수 있다"고 지적하는 구조로 간다.
이것 자체가 면접 연습이다.

**단, 코드 주석은 2026-09-02에 Claude에게 넘겼다.**
A등급 코드도 본체는 내가 쓰지만 주석은 Claude가 단다.
주석을 직접 쓰고 → 첨삭받고 → 고치고 → 다시 첨삭받는 왕복이 너무 비쌌다.
`verify_counts.py` 하나에 주석 라운드만 3회가 들어갔고, 그때 일정은 이미 2주 이상 밀려 있었다.
10절의 "일정이 밀릴 때 A등급 일부를 B로 강등"을 적용한 것이다.

강등 금지 항목(8·9·11·12·13·21)에는 해당하지 않는다.
저 여섯 개는 **판단**을 다루는 작업이고, 주석은 이미 내린 판단을 **설명하는 글**이라 성격이 다르다.

**대신 두 가지는 남긴다.**

- 읽고 틀린 주석은 내가 고친다. Claude가 코드를 잘못 이해하고 쓴 주석은 나만 잡을 수 있다
- **3절 이해 게이트 5문항은 그대로 적용한다.** 주석을 Claude가 썼어도 다섯 질문에 답하지 못하면 커밋하지 않는다
