# 1. 프로젝트 요약

## 1.1 한 문장 정의

> **직접 촬영·라벨링한 볼트·너트·와셔 이미지로 YOLO 모델을 파인튜닝하고, WPF 검사 프로그램에서 촬영한 이미지를 FastAPI로 보내 부품 수량을 판정한 뒤, 결과를 Microsoft SQL Server에 누적하고 Excel 보고서로 추출하는 AI 비전 검사 시스템**

## 1.2 목적

- AI 비전 검사 직무 취업을 위한 **1인 포트폴리오 프로젝트**
- 기간: 약 6주 (2026-08-07 시작)
- 핵심은 "스마트팩토리 전체 구현"이 아니라 **검사 장비 1대의 소프트웨어를 축소 구현**하는 것

## 1.3 프로젝트의 무게 중심

```text
AI 모델 튜닝·개선 과정  ← 여기가 핵심 (70%)
WPF / FastAPI / MSSQL / Excel  ← AI가 실제로 쓰이는 흐름을 보여주는 도구 (30%)
```

문서 전반에서 일관되게 강조되는 원칙이며, WPF 디자인이나 DB 정규화에 시간을 쓰지 않기로 이미 결정되어 있다.

# 2. 검사 대상과 판정 기준

## 2.1 대상

| 항목 | 내용 |
|---|---|
| 검사물 | 나무 트레이 위에 배치된 조립 부품 |
| 클래스 | `bolt`, `nut`, `washer` (3종) |
| 1차 검사 항목 | **각 부품이 기준 수량만큼 존재하는가** (존재 여부 + 개수) |
| 초기 기준 수량 | bolt 1, nut 1, washer 1 → 실물 확인 후 조정 |

## 2.2 판정 로직

```text
OK : 탐지 개수 == 기준 수량 (모든 클래스)
NG : 탐지 개수 <  기준 수량 (누락)
NG : 탐지 개수 >  기준 수량 (과다)
```

**중요한 역할 분담 (이미 확정됨):**

```text
YOLO           = 이미지에서 "무엇이 몇 개 보이는지" 탐지만 한다
Python 검사 로직 = 기준 수량과 비교하여 OK / NG를 판정한다
```

즉 `normal` / `defect` 를 클래스로 학습시키지 않는다. 부품 이름을 클래스로 두고, 판정은 규칙 코드가 담당한다. 이는 **검사 기준이 바뀌어도 재학습 없이 대응 가능**하다는 설계상의 장점이 있고, 면접에서 설명하기 좋은 포인트다.

## 2.3 1차 범위에서 제외 (선택적 고도화)

부품 위치 검사 / 방향 검사 / 스크래치·흠집 검사 / 잘못된 부품 검사

# 3. 시스템 구조

## 3.1 아키텍처

```text
┌──────────────────────────────────────────┐
│ WPF 데스크톱 검사 프로그램                 │
│ C# / .NET / XAML                          │
│ 카메라 영상 · 검사 시작 · OK/NG 표시       │
│ 검사 이력 조회 · Excel 내보내기            │
└───────────────┬──────────────────────────┘
                │ HTTP (multipart/form-data 업로드, JSON 응답)
                ▼
┌──────────────────────────────────────────┐
│ FastAPI 애플리케이션 (단일 프로세스)        │
│  ├─ 이미지 수신 (UploadFile)              │
│  ├─ YOLO 추론 (서버 시작 시 1회 로딩)      │
│  ├─ 부품별 개수 계산 → OK/NG 판정          │
│  ├─ 원본·결과 이미지 파일 저장             │
│  ├─ 검사 이력 DB 저장/조회                │
│  └─ Excel(.xlsx) 생성                     │
└───────────────┬──────────────────────────┘
                │ SQLAlchemy → pyodbc → ODBC Driver 18
                ▼
┌──────────────────────────────────────────┐
│ Microsoft SQL Server                      │
│ inspections 테이블 (검사 이력 중앙 저장)    │
└──────────────────────────────────────────┘
```

## 3.2 이미 확정된 구조적 결정

| 결정 | 내용 | 이유 |
|---|---|---|
| AI 서버 분리 안 함 | FastAPI 내부에서 추론·판정·저장을 모두 처리 | 6주 일정에서 불필요한 통신 계층 제거 |
| WPF는 DB 직접 접속 안 함 | 모든 DB 접근은 FastAPI 경유 | 책임 분리, 확장성 |
| 이미지는 파일로 저장, DB엔 경로만 | `storage/` 저장 후 경로 컬럼 | DB 비대화 방지 (면접 단골 질문) |
| 테이블 1개로 시작 | `inspections` 단일 테이블 | 과도한 설계 회피 |
| Code-behind 먼저, MVVM은 나중 | WPF 흐름 완성 우선 | 학습 부담 분산 |
| ONNX는 1차 제외 | Python 추론으로 먼저 완성 | C# 전처리·NMS 직접 구현 부담 |

## 3.3 검사 흐름 (14단계)

기준 수량 설정 → 부품 배치 → [검사 시작] → 이미지 캡처 → FastAPI 전송 → YOLO 추론 → 개수 비교 → OK/NG 판정 → 이미지·결과 저장 → MSSQL 저장 → JSON 응답 → WPF 결과 표시 → 이력 조회 → Excel 추출

## 4.5 데이터베이스

| 기술 | 역할 | 필수 | 비고 |
|---|---|---|---|
| **Microsoft SQL Server (Developer Edition)** | 검사 이력 중앙 저장 | ★필수 | 개발·테스트 목적 무료 |
| **SQL Server Management Studio (SSMS)** | DB·테이블·쿼리 직접 확인 | ★필수 | |
| **Microsoft ODBC Driver 18 for SQL Server** | Windows ODBC 계층 | ★필수 | ⚠️ **별도 설치 필요**, 기본값 `Encrypt=yes` |
| **`pyodbc`** | Python ↔ ODBC 연결 드라이버 | ★필수 | |
| **SQLAlchemy (2.x)** | ORM. Python 객체 ↔ 테이블 매핑 | ★필수 | MSSQL dialect: `mssql+pyodbc` |
| **Alembic** | 스키마 마이그레이션 | ★필수 | |
| ~~`psycopg` / `psycopg2`~~ | — | ❌**사용 안 함** | PostgreSQL 전용. 계획서에서 삭제됨 |

**연결 경로:**
```text
FastAPI → SQLAlchemy → pyodbc → ODBC Driver 18 → Microsoft SQL Server
```

**연결 문자열 (개념형):**
```python
DATABASE_URL = (
    "mssql+pyodbc://db_user:{암호}@localhost/vision_inspection"
    "?driver=ODBC+Driver+18+for+SQL+Server"
    "&TrustServerCertificate=yes"     # Driver 18은 기본이 암호화 요구 → 로컬 개발에 필수
)
```
실제 값은 코드가 아닌 **`.env`** 에 두고, `.env`는 커밋하지 않는다.

**MSSQL을 선택한 이유(면접 답변용):** C#·WPF 기반 제조·검사장비 소프트웨어 생태계와 조합이 맞고(C#+WPF+MSSQL은 스마트팩토리·MES 현장에서 흔한 스택), SSMS로 데이터를 직접 검증할 수 있으며, 서버형 DB의 계정·권한·연결 문자열 개념을 경험할 수 있기 때문. **AI 성능과는 무관**하며 DB의 역할은 "AI 검사 결과를 업무 데이터로 누적·조회하는 것"이다.

# 5. 데이터베이스 설계 (1차)

## 5.1 `inspections` 테이블

| 컬럼 | SQL Server 타입 | 설명 |
|---|---|---|
| `id` | `BIGINT IDENTITY(1,1)` | PK, 자동 증가 |
| `product_id` | `NVARCHAR(100)` | 제품 번호 |
| `inspected_at` | `DATETIME2` | 검사 시간 |
| `result` | `NVARCHAR(10)` | `OK` / `NG` |
| `defect_type` | `NVARCHAR(100)` | 불량 유형 |
| `detected_parts` | `NVARCHAR(MAX)` | 탐지 결과 JSON 문자열 |
| `missing_parts` | `NVARCHAR(MAX)` | 누락 부품 JSON 문자열 |
| `confidence` | `FLOAT` | 대표 신뢰도 |
| `inference_ms` | `INT` | 추론 시간 |
| `model_version` | `NVARCHAR(50)` | 모델 버전 |
| `original_image_path` | `NVARCHAR(500)` | 원본 이미지 경로 |
| `result_image_path` | `NVARCHAR(500)` | 결과 이미지 경로 |
| `created_at` | `DATETIME2` | 생성 시각 |

**참고:** SQL Server에는 PostgreSQL의 `JSONB`에 해당하는 자료형이 없어 `NVARCHAR(MAX)` + JSON 문자열로 저장한다. 필요 시 `ISJSON()`, `JSON_VALUE()` 함수로 조회 가능하다.
