- **`verify_counts.py`가 `images.csv`를 자동으로 고치게 만들지 말 것** — 어긋남이 CSV 탓인지 라벨 탓인지는 사진을 봐야 안다. **찾는 도구와 고치는 도구는 분리한다.** 자동으로 고치는 스크립트는 잘못 짰을 때 원본을 통째로 망가뜨리고 되돌릴 수도 없다
- **`dataset/export/`에 export를 두 벌 이상 쌓지 말 것** — `LABEL_PATH`가 `export`까지만 잡고 `*/labels/*.txt`로 훑기 때문에 같은 이름이 두 번 걸린다. 지금은 중복을 만나면 스크립트가 멈추게 해뒀다. 다시 내보낼 때는 **이전 폴더를 지우거나 옮긴다**
- ~~`labeling-guide.md` 3절 없이 라벨링 시작 금지~~ → **3절 작성 완료(8/23).** 대신 라벨링 중 규칙을 바꾸면 **반드시 8절 표에 기록**한다. 안 남기면 한 데이터셋에 두 규칙이 섞인다
- **⭐ 크롭하기 전에 라벨링하지 말 것** — 라벨을 그린 뒤에 자르면 잘라낸 만큼 그림이 밀려 **박스 좌표가 전부 어긋난다.** 순서는 `origin → rename → crop → 라벨링`이다. 웹캠 세션에만 해당한다(아이폰은 1:1로 저장되어 크롭이 필요 없다)
- **`metadata/`를 `dataset/` 안으로 옮기지 말 것** — `.gitignore`가 `dataset/`을 통째로 제외한다. CSV는 실패 분석의 유일한 근거라 git에 남아야 한다
- 이미지 / `.pt` 모델 / 데이터셋을 git에 커밋 금지
- Train/Val/Test를 랜덤 셔플로 분할 금지 — **반드시 촬영 세션 단위** (D-003)
