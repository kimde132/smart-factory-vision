## 이 문서를 쓰는 방법

**최신 항목을 맨 위에 쓴다.** 새 세션을 시작할 때 위에서 두세 개만 읽으면 최근 상황이 잡힌다.

`status.md`와 역할이 다르다.

| | 담는 것 | 낡으면 |
|---|---|---|
| `status.md` | **지금** 상태 — 다음 할 일, 막힌 것 | **지운다** (Claude가 갱신) |
| `daily-log.md` | **그날** 있었던 일 | **남긴다.** 지우지 않는다 |

### 항목 다섯 개

- **한 일** — 결과물 기준으로. "D-008 작성" 처럼 무엇이 남았는지
- **막힌 것 / 어떻게 풀었나** — 풀지 못했으면 못했다고 쓴다. 그게 다음 날의 출발점이다
- **환경·설정 변경** — 아래 설명 참고. **이 칸이 이 일지의 핵심이다**
- **다음에 이어서** — 그날 끊긴 지점
- **메모 / 궁금한 것** — 나중에 물어볼 것, 떠오른 아이디어

### 왜 "환경·설정 변경" 칸이 따로 있나

이 프로젝트에서 가장 중요한 작업은 **실패 사례 분석**(work-grades #21)이다.
성능이 떨어졌을 때 원인을 찾으려면 **"언제 무엇을 바꿨는지"** 를 알아야 한다.

- 조명 위치나 밝기를 바꿨다
- 카메라를 폰에서 웹캠으로 바꿨다
- 촬영 거리나 프레임 폭을 바꿨다
- 라벨링 규칙을 수정했다
- 기준 수량이나 학습 설정값을 바꿨다

이런 것을 그날 적어두지 않으면, 3주 뒤에 "8월 중순부터 데이터가 이상한데 뭘 바꿨었지"를 알 수 없다.
바꾼 게 없으면 `없음`이라고 쓴다. 비워두면 안 적은 건지 안 바꾼 건지 구분이 안 된다.
