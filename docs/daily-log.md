## 이 문서를 쓰는 방법

**최신 항목을 맨 위에 쓴다.** 새 세션을 시작할 때 위에서 두세 개만 읽으면 최근 상황이 잡힌다.

`status.md`와 역할이 다르다.

| | 담는 것 | 낡으면 |
|---|---|---|
| `status.md` | **지금** 상태 — 다음 할 일, 막힌 것 | **지운다** (Claude가 갱신) |
| `daily-log.md` | **그날** 있었던 일 | **남긴다.** 지우지 않는다 |

### 항목 다섯 개

- **한 일** — 결과물 기준으로. "D-008 작성" 처럼 무엇이 남았는지
- **막힌 것 / 어떻게 풀었나** — 풀지 못했으면 못했다고 쓴다. 그게 다음 날의 출발점이다
- **환경·설정 변경** — 아래 설명 참고. **이 칸이 이 일지의 핵심이다**
- **다음에 이어서** — 그날 끊긴 지점
- **메모 / 궁금한 것** — 나중에 물어볼 것, 떠오른 아이디어

### 왜 "환경·설정 변경" 칸이 따로 있나

이 프로젝트에서 가장 중요한 작업은 **실패 사례 분석**(work-grades #21)이다.
성능이 떨어졌을 때 원인을 찾으려면 **"언제 무엇을 바꿨는지"** 를 알아야 한다.

- 조명 위치나 밝기를 바꿨다
- 카메라를 폰에서 웹캠으로 바꿨다
- 촬영 거리나 프레임 폭을 바꿨다
- 라벨링 규칙을 수정했다
- 기준 수량이나 학습 설정값을 바꿨다

이런 것을 그날 적어두지 않으면, 3주 뒤에 "8월 중순부터 데이터가 이상한데 뭘 바꿨었지"를 알 수 없다.
바꾼 게 없으면 `없음`이라고 쓴다. 비워두면 안 적은 건지 안 바꾼 건지 구분이 안 된다.

- **`split('\')` 에 빨간 줄이 떴는데 이유를 몰랐다.** 백슬래시가 **이스케이프 문자**라 뒤따르는 따옴표를 글자로 먹어버려 문자열이 안 닫힌 것이었다. `'\\'` 로 해결. 경로를 문자열로 다루면 골치 아프고 `pathlib`을 쓰는 이유가 이것이라는 것도 같이 확인했다
- **`CLASS_NAME[line[0]]` 이 `KeyError: '1'`.** 파일에서 읽은 `line[0]`은 숫자 `1`이 아니라 **글자 `'1'`** 이다. `int()`로 풀었다. 겸해서 `line[0]`(첫 글자) 대신 `line.split()[0]`(공백으로 쪼갠 첫 조각)으로 바꿨다 — 클래스가 10번을 넘으면 첫 글자만 읽고 조용히 틀리기 때문
- **CSV에서 읽은 값도 전부 문자열이었다.** `'0' != 0` 이라 그대로 뒀으면 **35장 전부 불일치로 나왔을 것**이다. `int()`로 감쌌다
- **파일명에서 이름을 뽑을 때 처음엔 `filename[-11:]` 로 잘랐다.** `.txt` 4글자가 딸려와 `s01_022.txt`가 나왔다. 자릿수를 고쳐도 되지만 **`-11`이 매직 넘버**라 가정이 깨지면 에러 없이 조용히 틀린 값을 낸다는 지적을 받고, `unquote` → `\` 로 쪼개기 → `.stem` 순서로 바꿨다
- **`result.replace('.txt', '')` 의 결과를 안 받아서 아무 일도 안 일어났다.** 파이썬 문자열은 **불변**이라 메서드가 원본을 고치지 않고 새 문자열을 돌려준다. `list.append()`와 반대라 헷갈리는 자리다
- **`LABEL_PATH`를 `dataset/export`로 잡았더니 라벨을 하나도 못 찾았다.** 라벨은 `export/<프로젝트폴더>/labels/` 두 단계 아래에 있다. `glob('*/labels/*.txt')`로 훑어서 풀었다
- **`[개수 검사]` 제목 줄을 `for` 문 뒤에 뒀다가 목록 아래에 찍혔다.** 반복문 앞으로 올렸다
