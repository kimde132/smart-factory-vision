### 왜 "환경·설정 변경" 칸이 따로 있나

이 프로젝트에서 가장 중요한 작업은 **실패 사례 분석**(work-grades #21)이다.
성능이 떨어졌을 때 원인을 찾으려면 **"언제 무엇을 바꿨는지"** 를 알아야 한다.

- 조명 위치나 밝기를 바꿨다
- 카메라를 폰에서 웹캠으로 바꿨다
- 촬영 거리나 프레임 폭을 바꿨다
- 라벨링 규칙을 수정했다
- 기준 수량이나 학습 설정값을 바꿨다

이런 것을 그날 적어두지 않으면, 3주 뒤에 "8월 중순부터 데이터가 이상한데 뭘 바꿨었지"를 알 수 없다.

- **박스를 "여유 있게" 그린다고 결론냈는데 뒤집었다.** 기울어진 부품은 딱 맞게 그릴 수 없다고 생각했는데, YOLO 박스는 **축 정렬**이라 회전하지 않는다는 것을 몰랐다. 기울어져도 최외곽 네 점에 맞추면 되니 "딱 맞게"가 성립한다
- **일관성이 없으면 왜 학습에 불리한지 몰랐다.** 같은 물체에 서로 다른 정답 좌표가 들어오면 모델이 두 정답 중간으로 수렴해 어느 쪽도 맞히지 못한다는 설명으로 풀렸다. 라벨의 흔들림이 성능의 천장이 된다
- **CSV 대신 DB를 쓰는 이유를 절반만 알고 있었다.** 동시 접근 문제는 운영체제 과목에서 배운 감각으로 짚었지만, 조회 과정과 제약 조건 이야기는 몰랐다. 처음엔 "엑셀 저장 한도"를 근거로 썼는데 그건 사실이 아니어서 버렸다
- **SQL Server 설치 실패 4건이 무슨 문제였는지 몰랐다.** 경로 260자 한계 / PowerShell CP949 인코딩 / 콘솔 종료로 인한 강제 종료 / 반쪽 설치가 남긴 master.mdf. 설명을 듣고 이 중 셋은 MSSQL 고유 비용이 아니라 **무인 설치 방식을 택한 비용**이라는 구분을 배웠다

**환경·설정 변경**
- **클래스 번호 확정: 0=bolt, 1=nut, 2=washer.** 라벨링 시작 후 순서를 바꾸지 않는다
- **박스 규칙 확정: 축 정렬 최외곽 밀착(tight).** 여유를 두면 인접 부품 박스가 겹쳐 NMS가 하나를 지우고 개수가 틀어짐
- **볼트는 눕혀서 배치.** 볼트 머리와 너트가 탑뷰에서 크기·모양이 같아 세우면 구분 단서가 중앙 구멍 유무 하나로 줄어듦
