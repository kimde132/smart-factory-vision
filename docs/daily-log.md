> 특히 조명 위치, 트레이를 놓은 자리처럼 기록에 남지 않은 것은 빠져 있다.

## 이 문서를 쓰는 방법

**최신 항목을 맨 위에 쓴다.** 새 세션을 시작할 때 위에서 두세 개만 읽으면 최근 상황이 잡힌다.

`status.md`와 역할이 다르다.

| | 담는 것 | 낡으면 |
|---|---|---|
| `status.md` | **지금** 상태 — 다음 할 일, 막힌 것 | **지운다** (Claude가 갱신) |
| `daily-log.md` | **그날** 있었던 일 | **남긴다.** 지우지 않는다 |

### 항목 다섯 개

- **한 일** — 결과물 기준으로. "D-008 작성" 처럼 무엇이 남았는지
- **막힌 것 / 어떻게 풀었나** — 풀지 못했으면 못했다고 쓴다. 그게 다음 날의 출발점이다
- **환경·설정 변경** — 아래 설명 참고. **이 칸이 이 일지의 핵심이다**
- **다음에 이어서** — 그날 끊긴 지점
- **메모 / 궁금한 것** — 나중에 물어볼 것, 떠오른 아이디어

### 왜 "환경·설정 변경" 칸이 따로 있나

이 프로젝트에서 가장 중요한 작업은 **실패 사례 분석**(work-grades #21)이다.
성능이 떨어졌을 때 원인을 찾으려면 **"언제 무엇을 바꿨는지"** 를 알아야 한다.

- 조명 위치나 밝기를 바꿨다
- 카메라를 폰에서 웹캠으로 바꿨다
- 촬영 거리나 프레임 폭을 바꿨다
- 라벨링 규칙을 수정했다
- 기준 수량이나 학습 설정값을 바꿨다

이런 것을 그날 적어두지 않으면, 3주 뒤에 "8월 중순부터 데이터가 이상한데 뭘 바꿨었지"를 알 수 없다.
바꾼 게 없으면 `없음`이라고 쓴다. 비워두면 안 적은 건지 안 바꾼 건지 구분이 안 된다.

## 2026-08-12 (수)

**한 일**
- D-008 작성 — 정상 수량 기준과 데이터의 수량 다양성
- D-007 마무리 정리 (2절을 변수 구분 / 확정 수치 / 카메라 고정 방법으로 분리)
- `foundations.md` 2-5~2-8절 추가 — 축 정렬 박스, NMS와 IoU, 배경 이미지, 해상도 예산
- `status.md` 신설 (진행 상황 상태판) + `CLAUDE.md`에 등재
- `daily-log.md` 골격 신설

**막힌 것 / 어떻게 풀었나**
- **모델이 개수를 센다고 오해했다.** "학습 데이터에 3개짜리가 많으면 3개라고 답할 확률이 높아진다"는 설명이 이해가 안 됐다. 물어보니 그 설명 자체가 과장이었고, YOLO에는 개수를 출력하는 부분이 아예 없다는 것을 확인했다. 진짜 문제는 개수가 늘면 **장면의 겉모습이 바뀐다**는 것 — 간격이 좁아지고 겹치고 그림자가 겹치는 상황을 학습에서 본 적이 없으면 박스가 부정확해지고 NMS에 지워진다
- **"기준이 언제 바뀌었는지를 남길 수 없다"가 무슨 뜻인지 몰랐다.** 측정 도구 문제인가 했는데, 기준 수량을 나중에 바꾸면 과거 검사 기록을 해석할 수 없게 된다는 뜻이었다. D-006의 모델 버전 저장과 같은 구조다
- 정상 수량 1개가 왜 문제인지 처음엔 안 보였다. 부족이 0개 하나뿐이고 초과가 2~6개로 비대칭이라는 지적을 받고 3개로 바꿨다

**환경·설정 변경**
- **정상 수량 기준을 각 1개 → 각 3개로 변경.** 부족(0~2)과 초과(4~6)가 대칭이 되고, 각 1개면 "있나 없나" 검사에 가까워지는 문제를 해소
- 촬영 수량 범위를 0~6개, 각 개수마다 5장으로 정함
- 부품을 3개씩 추가 주문 (부품당 6개 확보 예정)

**다음에 이어서**
- **#10 파일명·세션 명명 규칙.** 지금 본 촬영을 막고 있는 유일한 항목
- 부품 도착 후 **18개(6+6+6)가 20cm 프레임에 서로 닿지 않게 들어가는지 확인**

**메모 / 궁금한 것**
- 18개가 안 들어가면 정상 3개와 상한 6개를 다시 봐야 한다. 프레임을 넓히는 건 **31cm까지만** 가능 (그 이상이면 와셔가 40픽셀 아래로 떨어짐)
- 문서화에 시간이 많이 들어가고 있다. 일지를 Claude 초안 + 내가 확인하는 방식으로 바꿨다 (D-001 뒤집는 조건 적용)

## 2026-08-11 (화)

**한 일**
- D-007 작성 완료 — 촬영 환경 설계와 파일럿 결과
- 해상도 예산 계산 (프레임 20cm에서 와셔 약 63픽셀, 목표 40픽셀 충족)
- **D-004를 잠정 → 확정으로 변경** (파일럿에서 너트·와셔 구분 확인)

**막힌 것 / 어떻게 풀었나**
- **NMS를 몰라서 박스 규칙의 근거를 완성하지 못했다.** 설명을 듣고 나서야 "박스를 크게 그리면 인접 부품 박스가 겹쳐 NMS가 하나를 지우고 개수가 틀어진다"를 근거로 쓸 수 있었다
- **반사광이 "부품 밖에 있다"는 말이 이해가 안 됐다.** 표면의 반사광인데 표면 밖이라는 게 모순처럼 보였다. 금속 반사가 바닥을 비추는 경우와 센서에서 빛이 번지는 경우 두 가지라는 설명으로 풀렸다. 후자가 심하면 너트 육각 모서리가 먹혀 와셔처럼 보일 수 있다
- **너트 외경 15.9mm와 와셔 19.6mm를 그대로 비교했다.** 15.9는 육각형의 대변이고 탑뷰에서 보이는 최대 폭은 대각선(약 18.4mm)이라, 실제 차이는 23%가 아니라 **6%뿐**이었다. 크기를 구분 단서로 쓸 수 없다는 결론이 여기서 나왔다
- 손 촬영의 문제를 "이전 세션과 똑같아져서 데이터 누수가 생긴다"로 잘못 파악했다. 실제 문제는 그 반대 — 매번 달라져서 세션이 하나의 조건을 대표하지 못하는 것이었다

**환경·설정 변경**
- **자연광 배제, 실내 조명(후방)만 사용.** 시간대·날씨에 따라 변해 재현할 수 없어서 커튼으로 차단
- **렌즈를 아이폰 15 Pro 광각으로 확정.** 망원은 20cm 프레임에 필요한 거리를 확보할 수 없음. 대신 원근 왜곡을 감수
- 프레임 20cm × 20cm 확정
- 거치 기구가 없어 손 촬영으로 진행. 프레임 폭은 "트레이 20cm 변이 꽉 차게"로 통제하고, 각도 흔들림은 감수

**다음에 이어서**
- D-008 작성 — 정상 수량 기준과 데이터의 수량 다양성

**메모 / 궁금한 것**
- 측정 도구가 없어 카메라 높이를 수치로 기록하지 못했다. 아이폰 `계측` 앱이나 A4 용지(297mm)로 근사 측정을 시도해볼 것
- 부품 치수는 상품 페이지 규격이고 실측이 아니다. 와셔 외경 19.6mm는 해상도 예산과 6% 계산의 근거라서 나중에 자로 검증할 것

**한 일**
- D-004·D-005·D-006 작성 (검사 대상 3종 / 빈 트레이는 배경 이미지 / DB는 MSSQL)

- D-007 초안 작성 시작

**막힌 것 / 어떻게 풀었나**
- **박스를 "여유 있게" 그린다고 결론냈는데 뒤집었다.** 기울어진 부품은 딱 맞게 그릴 수 없다고 생각했는데, YOLO 박스는 **축 정렬**이라 회전하지 않는다는 것을 몰랐다. 기울어져도 최외곽 네 점에 맞추면 되니 "딱 맞게"가 성립한다
- **일관성이 없으면 왜 학습에 불리한지 몰랐다.** 같은 물체에 서로 다른 정답 좌표가 들어오면 모델이 두 정답 중간으로 수렴해 어느 쪽도 맞히지 못한다는 설명으로 풀렸다. 라벨의 흔들림이 성능의 천장이 된다
- **CSV 대신 DB를 쓰는 이유를 절반만 알고 있었다.** 동시 접근 문제는 운영체제 과목에서 배운 감각으로 짚었지만, 조회 과정과 제약 조건 이야기는 몰랐다. 처음엔 "엑셀 저장 한도"를 근거로 썼는데 그건 사실이 아니어서 버렸다
- **SQL Server 설치 실패 4건이 무슨 문제였는지 몰랐다.** 경로 260자 한계 / PowerShell CP949 인코딩 / 콘솔 종료로 인한 강제 종료 / 반쪽 설치가 남긴 master.mdf. 설명을 듣고 이 중 셋은 MSSQL 고유 비용이 아니라 **무인 설치 방식을 택한 비용**이라는 구분을 배웠다

**환경·설정 변경**
- **클래스 번호 확정: 0=bolt, 1=nut, 2=washer.** 라벨링 시작 후 순서를 바꾸지 않는다
- **박스 규칙 확정: 축 정렬 최외곽 밀착(tight).** 여유를 두면 인접 부품 박스가 겹쳐 NMS가 하나를 지우고 개수가 틀어짐
- **볼트는 눕혀서 배치.** 볼트 머리와 너트가 탑뷰에서 크기·모양이 같아 세우면 구분 단서가 중앙 구멍 유무 하나로 줄어듦

**다음에 이어서**
- D-007 검토받고 파일럿 결과 정리

**메모 / 궁금한 것**
- 거치대를 살지 손 촬영을 유지할지 고민 중. 책 쌓기나 상자에 구멍 뚫는 방법을 제안받았다
- 파일럿 사진은 임시 폴더에 두었다. #10 명명 규칙이 정해지면 정리하거나 버릴 것
